무엇인가

MetaDRAG® 는 데이터 표준화 설계부터 온톨로지 기반의 시맨틱 엔진 구현까지 3단계를 거쳐 기업의 레거시 데이터를 지능형 비즈니스 객체로 전환하는 엔터프라이즈 데이터 엔지니어링 프레임워크입니다.

왜 메타데이터부터인가

기업 데이터베이스에 AI 를 붙일 때 가장 먼저 부딪히는 것은 모델의 성능이 아니라 데이터가 무엇인지 아무도 정확히 모른다는 사실입니다. 테이블 이름은 줄임말이고, 같은 뜻의 컬럼이 시스템마다 다른 이름으로 있으며, 코드값의 의미는 오래 다닌 사람의 머릿속에 있습니다.

이 상태에서 자연어 질의를 붙이면 AI 는 모르는 것을 모른다고 하지 않고 그럴듯한 SQL 을 지어냅니다. 틀린 숫자가 맞는 모양으로 나오는 것이 데이터 프로젝트에서 가장 비싼 실패입니다.

MetaDRAG® 는 그 앞단을 맡습니다. 표준을 세워 메타데이터를 정리하고, 흩어진 데이터를 하나의 층으로 합성한 다음, 의미와 관계가 명시된 객체로 바꿔 AI 에 넘깁니다.

Workflow

단계별로 무엇을 하는가

앞 단계의 산출물이 다음 단계의 입력이 됩니다. 건너뛰면 뒤에서 메웁니다.

01

Design

Data Standardization Designer

  • DAMA-DMBOK Architecture 글로벌 데이터 관리 표준 프레임워크 체계를 기반으로 데이터 거버넌스 구조를 설계합니다.
  • Standard Data Modeling 기업 전반의 용어와 도메인을 체계화하는 표준 데이터 모델링을 수행합니다.
  • OECD Data Quality Control OECD 데이터 품질 관리 기준을 적용해 신뢰성·정밀성·완전성을 검증합니다.

Artifact Standard Metadata Repository

02

Integration

M3 Synthesizer

  • Master Data Integration 기업의 핵심 기준 정보인 마스터 데이터를 통합 관리합니다.
  • Meta Data Mapping 표준 메타데이터 저장소와 연계해 데이터 간의 구조적 의미를 사상(Mapping)합니다.
  • Mart Data Structuring 분석과 RAG 에 최적화된 주제별 데이터 마트를 합성합니다.

Artifact M3 Dataset — Master · Meta · Mart

03

Implementation

Semantic Engine

  • Ontology Classes 데이터 엔티티를 의미론적 범주(Class)로 개체화합니다.
  • Ontology Relations 엔티티 간의 다차원 연관 관계(Relation)를 정의해 지식 네트워크를 구축합니다.
  • Ontology Rules 비즈니스 로직과 추론 규칙(Rule)을 이식해 인공지능이 이해할 수 있는 상태로 완성합니다.

Artifact Business Context Object

Why MetaDRAG®

무엇이 다른가

표준화된 고품질 거버넌스

DAMA-DMBOK 과 OECD 표준 품질 기준을 적용해 정밀한 메타데이터 기반을 세웁니다. 표준 없이 모은 메타데이터는 또 하나의 정리되지 않은 더미입니다.

M3 다차원 데이터 합성

마스터·메타·마트 데이터를 유기적으로 연결해 데이터 유실 없는 통합 레이어를 만듭니다. 셋 중 하나만 빠져도 그 자리에서 맥락이 끊깁니다.

실시간 맥락 추론

단순히 데이터를 저장하는 데서 그치지 않고 비즈니스 규칙과 관계성이 명시된 객체로 바꿉니다. RAG 의 환각을 근본에서 줄이는 자리가 여기입니다.

Features

제품에서 하는 일

위의 세 단계를 사람이 화면에서 밟아 나가는 방식입니다.

스키마 수집과 동기화

운영 중인 데이터베이스에서 테이블·컬럼·제약을 읽어 옵니다. 바뀌면 차이를 보여주고, 사람이 확인한 뒤 반영합니다.

화면에서 하는 설계

ERD 문서를 따로 그리고 실제 DB 와 어긋나게 두지 않습니다. 설계와 현물이 같은 자리에 있습니다.

이름 · 도메인 표준

같은 뜻에 같은 이름을 씁니다. 표준을 한 곳에 두면 새 시스템이 늘어도 갈라지지 않습니다.

의미 기반 검색

「매출이 들어 있는 컬럼」 처럼 뜻으로 찾습니다. 이름을 정확히 알아야 찾을 수 있으면 검색이 아닙니다.

AI 질의의 근거 공급

정리된 메타데이터를 컨텍스트로 넘겨 질의를 만듭니다. 추측이 아니라 실제 구조 위에서 답합니다.

영향도 추적

컬럼 하나를 바꾸면 어디가 깨지는지 먼저 봅니다. 바꾸고 나서 아는 것과는 값이 다릅니다.

이런 곳에 맞습니다

  • 오래 운영한 시스템이 여러 개이고, 같은 데이터가 여기저기 다른 이름으로 있는 곳
  • 데이터 요청을 받을 때마다 담당자가 SQL 을 새로 짜고 있는 곳
  • AI 도입을 검토했으나 「우리 데이터로는 안 될 것 같다」 에서 멈춘 곳
  • 차세대 · 마이그레이션을 앞두고 현행 구조를 정확히 파악해야 하는 곳
